# ADR-0001: CLI 구현을 위한 논의

- **상태**: Accepted (2026-08-23 — 착수 시점을 조기 착수로 변경, 하단 갱신 참조)
- **날짜**: 2026-08-22
- **관련 문서**: [Nullus CLI 컨셉](../11_기능설계/Nullus_CLI_컨셉.md) · [CLI+MCP 구현 백로그](../plans/2026-08-22-cli-mcp-구현-백로그.md) · EPIC [nullus-plan#42](https://github.com/cloud-nullus/nullus-plan/issues/42)

## Context

통합 `nullus` CLI 컨셉 문서(2026-08-15)에 대한 검토를 2026-08-22 수행했다. 문서의 사실 관계를 코드와 전수 대조한 결과 모두 일치했다:

| 문서 주장 | 코드 확인 |
|---|---|
| 목적특화 도구 3종 존재 | `cmd/nullus-bootstrap`(issue/revoke), `cmd/token-source-sync`, `scripts/runbook_local.sh` ✓ |
| cobra는 indirect 의존만 | `go.mod` `spf13/cobra // indirect` ✓ |
| API 약 118개 | 핸들러 라우트 등록 119개 ✓ |
| WS 로그 엔드포인트 | `internal/stack/adapter/handler/deploy_handler.go` `/ws/deployments/:id/logs` ✓ |
| F5·F6 "안정화 진행 중" | README 기능 구현 현황 ✓ |
| `auth.mode=session\|oidc` | `configs/config.yaml` ✓ |

**CLI 제공의 기술적 장벽은 없다** — REST API 119개가 가동 중이고, 헤드리스 인증(`nullus-bootstrap issue`)과 OIDC 기반(`internal/auth`), WS 로그 스트림이 이미 존재한다. CLI는 별도 백엔드 없이 이 API를 호출하는 얇은 클라이언트로 성립한다. 남은 것은 착수 시점과 선행 설계다.

## Decision (제안)

CLI 구현을 전제로, 착수 조건과 선행 작업을 다음과 같이 고정할 것을 제안한다.

1. **착수 시점**: F5·F6(CI/CD 파이프라인)이 README 기능 현황에서 "안정화 진행 중"→"구현됨"으로 전환되는 시점. 현재 최근 커밋(#205~#207)이 전부 stack/cicd API를 변경 중이라, 지금 착수하면 웹·CLI 이중 유지비가 발생한다.
2. **명령 체계·범위는 컨셉 문서대로 고정**: noun-verb 구조, 1급(automation 핵심)/2급(선택)/제외(웹 유지) 구분, CLI = REST 얇은 클라이언트 원칙.
3. **착수 전 선행 작업 4건**:
   - `stack.yaml` 선언형 스키마 설계 — 서버에도 없는 개념이므로 별도 문서로 선행 확정. 웹 마법사에 "설정 yaml 내보내기"를 먼저 넣으면 스키마 검증을 겸할 수 있다
   - automation 계약 원칙 고정 — exit code 규약(배포 실패 vs CLI 오류 구분), `-o json` 출력 안정성, `--wait` 시맨틱. 열린 질문이 아니라 1급 명령의 성립 조건
   - 토큰 캐시 보안 명시 — `~/.nullus/` 파일 권한(0600), refresh token 취급, WS 인증(서브프로토콜) 경로
   - "RBAC이 명령 가시성을 규정" 문구 수정 — CLI는 호출 전 롤을 알 수 없으므로 실제로는 403 처리 UX

## Consequences

- CLI 착수 시점과 선행 작업이 명문화되어, 이후 논의는 "할지 말지"가 아니라 "조건 충족 여부" 확인으로 단순해진다.
- 착수 시점에 컨셉 문서에 반영할 추가 보완점: CLI–서버 버전 스큐 대응, 멀티 서버 컨텍스트(`~/.nullus/config`), 명명 일관성(`ls`/`get` 혼용, `pipeline` vs `cicd` 모듈명).
- `runbook_local.sh`의 `nullus dev` 편입은 비권장으로 기운다 — dev 도구 수명주기가 제품 릴리스에 묶이는 비용이 크다. 최종 결정은 착수 시점으로 미룬다.

## 갱신 (2026-08-23) — Proposed → Accepted, 착수 시점 변경

중간점검(2026-08-22)에서 CLI + MCP 연동을 **"빠른 시일 내 추가 구현"** 하기로 결정했다. 이에 따라 Decision 1항의 착수 시점(F5·F6 "구현됨" 전환 대기)을 폐기하고 **즉시 착수**로 변경한다.

- **감수하는 비용**: F5·F6 API가 아직 변경 중이므로, 변경 발생 시 웹·CLI/MCP 양쪽 추적 비용(이중 유지비)이 발생한다. 이를 인지하고 감수한다.
- **범위 조정 (2026-08-23)**: 2항의 명령 체계(noun-verb, 얇은 클라이언트 원칙)는 유지하되 범위를 확장한다 — **1급+2급을 전용 명령으로 구현**하고, 그 외 API(제외 영역)는 **`nullus api <METHOD> <path>` passthrough**(gh api 스타일)로 인증된 접근만 보장한다. REST 119개 전부를 전용 명령으로 만들지 않으며, 웹 UI가 1차 표면이라는 원칙과 `nullus dev` 비권장(Consequences)은 유지한다. 3항(선행 작업 4건)은 그대로 유효하며, 선행 작업은 [CLI+MCP 구현 백로그](../plans/2026-08-22-cli-mcp-구현-백로그.md) Phase 0(0-2~0-4)으로 편입됐다.
- **MCP 추가**: 중간점검 결정에 MCP 연동이 포함되어, 백로그는 공유 기반(`pkg/nullusclient`) 위 2트랙(CLI ∥ MCP) 병행 구조로 확장됐다. MCP 설계 문서 작성(0-4)이 선행 작업에 추가됐다.
