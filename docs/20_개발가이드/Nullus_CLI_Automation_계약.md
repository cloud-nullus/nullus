# Nullus CLI Automation 계약

- **상태**: 확정 (CLI+MCP 구현 백로그 0-3 산출물)
- **작성일**: 2026-08-23
- **관련 문서**: [Nullus CLI 컨셉](./Nullus_CLI_컨셉.md) §8 · [CLI+MCP 구현 백로그](../plans/2026-08-22-cli-mcp-구현-백로그.md) · [ADR-0001](../adr/0001-cli-구현을-위한-논의.md)

> CLI의 존재 이유는 "반복·자동화·헤드리스"다(컨셉 문서 §2). 따라서 아래 계약은 부가 기능이 아니라 **1급 명령의 성립 조건**이며, 트랙 A 전 명령이 이 계약을 따른다. 컨셉 문서 §8의 열린 질문 중 "automation 계약 표준"을 본 문서로 확정한다.

## 1. Exit Code 규약

핵심 원칙: **"CLI가 실패했는가"와 "요청한 작업이 실패했는가"를 구분한다.** 전자는 재시도·환경 점검 대상이고, 후자는 플랫폼에서 원인을 조사할 대상이다.

| Code | 의미 | 예시 |
|------|------|------|
| 0 | 성공 | 배포 완료, 조회 성공 |
| 1 | CLI 내부 오류 | 예기치 못한 패닉, 버그 |
| 2 | 사용법 오류 | 잘못된 플래그/인자, `stack.yaml` 스키마 유효성 실패 |
| 3 | 인증·권한 오류 | 토큰 없음/만료(401), RBAC 거부(403) |
| 4 | 대상 없음 | 스택/클러스터 ID 미존재(404) |
| 5 | 서버·연결 오류 | API 5xx, 연결 실패, 버전 비호환 |
| 6 | **작업 실패** | API 호출은 성공했으나 배포가 `failed`로 종료 (`--wait` 결과 포함) |
| 7 | 대기 타임아웃 | `--wait` 제한 시간 내 작업 미완료 (실패 아님 — 작업은 계속 진행 중) |

- 8~63은 예약. 명령별 추가 코드를 만들지 않는다 — 세부 원인은 stderr 메시지와 `-o json`의 상태 필드로 전달한다.
- HTTP 매핑: 400→2, 401/403→3, 404→4, 5xx/연결불가→5. 409 등 도메인 충돌은 2(요청이 현재 상태와 안 맞음)로 취급한다.

## 2. 출력 스트림 규율

- **stdout = 데이터, stderr = 사람**. 결과 데이터만 stdout에 쓴다. 진행 표시·경고·오류 메시지는 전부 stderr.
- 실패 시 stdout은 비운다(부분 출력 금지). 스크립트는 exit code로 성패를 판정하고, stdout은 성공 시에만 파싱한다.
- non-TTY(파이프/CI) 감지 시 진행 애니메이션·색상을 끈다. `--no-color`로 강제 가능.

## 3. `-o json` 안정성 계약

- 기본 출력은 사람용 표, `-o json` 지정 시 **단일 JSON 객체**를 stdout에 쓴다 (JSON Lines 아님, 후행 개행 1개).
- **CLI 출력 스키마는 서버 API 응답과 절연한다.** 서버 응답을 그대로 통과시키지 않고 명령별 출력 구조체를 CLI가 소유한다 — 서버 API가 진화해도(ADR-0001이 감수한 비용) CLI 출력 계약은 CLI 릴리스로만 변한다.
- 호환성 규칙: **필드 추가는 하위 호환**(스크립트는 모르는 필드를 무시해야 한다), 필드 제거·이름 변경·타입 변경은 **breaking** — CLI 메이저 버전에서만 허용.
- v0.x 동안은 계약이 변할 수 있다. v1.0부터 위 규칙을 고정한다.
- 리스트 출력은 `{"items": [...]}` 봉투를 쓴다 (최상위 배열 금지 — 메타 필드 추가 여지 확보).

## 4. `--wait` 시맨틱

- 기본은 **비대기**: 요청이 접수되면 즉시 exit 0 (조회 명령 제외). `--wait`를 줘야 종결 상태까지 대기한다.
- 대기 종료 조건과 exit code: 작업 `completed` → 0 · `failed` → 6 · 제한 시간 초과 → 7.
- `--timeout <duration>` (기본 `30m`)은 `--wait`와만 유효. 타임아웃은 **작업을 취소하지 않는다** — CLI만 떠난다.
- 대기 중 진행 상태는 stderr에만 표시. `--wait` + `-o json`이면 종결 시점의 최종 상태 1개 객체만 stdout에 쓴다.
- 폴링 주기는 구현 상세(기본 5s)로 계약이 아니다 — 스크립트는 주기에 의존하지 않는다.

## 5. 환경변수·비대화 원칙

- `NULLUS_SERVER`, `NULLUS_TOKEN` 등 `NULLUS_*` env가 설정 파일보다 우선한다 (CI에서 파일 없이 실행 가능). 우선순위: 플래그 > env > `~/.nullus/config`.
- 모든 명령은 **비대화식이 기본**이다. 프롬프트가 필요한 경우(파괴적 작업 확인 등) non-TTY에서는 즉시 exit 2 — `--yes`로 우회한다.
