## 처리 방침

문서를 통째로 다시 쓰지 않았다. 5개월치 설계 서술을 손으로 옮기면 옮기는 과정에서
사실이 또 틀어지고 다음 달이면 같은 문제가 반복된다. 대신 **코드에서 기계적으로 추출한
인벤토리를 권위 있는 기준으로 넣고, 사실이 바뀐 서술만 고쳤다.** 설계안은 설계안으로
남기되 "어디를 믿어야 하는지" 를 문서 머리에 명시했다.

문서 성격에 따라 다르게 다뤘다.

| 그룹 | 성격 | 방침 |
|------|------|------|
| A | 코드와 일치해야 하는 레퍼런스 | 코드 추출 인벤토리로 대체 |
| B | 가이드·절차 | 실행 실패하는 안내를 우선 수정 |
| C | 기획·전략 | 계획 표는 보존하고 달성도를 별도 장으로 추가 |
| D | 시점 기록 | **고치지 않는다.** 현재 일자 기준 새 문서를 작성 |

D 를 고치지 않는 이유는 그날의 판단을 남긴 기록이라 고쳐 쓰면 이력이 사라지기
때문이다. 대신 `20260811_현황.md` 를 새로 만들었다.

## 지난 회차의 오판 하나

2026-08-11 회차는 "Alert Rule 과 실제 알림 발송의 운영 연결" 을 **해소 항목으로 옮겼다.**
근거는 `internal/shared/notification/notifier.go` 와 `notification_configs`·
`notification_history` 테이블, `/admin/notifications/*` API 가 모두 존재한다는 것이었다.

**조각이 있는 것과 이어져 있는 것은 다르다.** 이번에 호출부를 따라가 보니 세 군데가 끊겨
있었다.

1. 규칙을 메트릭과 견주는 평가 루프가 없다 — `observability/usecase/` 에는 CRUD 뿐이다.
2. `SlackNotifier`·`EmailNotifier` 를 만드는 프로덕션 코드가 **한 곳도 없다.**
   `internal/shared/notification` 밖에서 이 타입을 참조하는 것은 테스트뿐이다.
3. `notification_history` 에 `INSERT` 하는 코드가 없다. 화면에 보이는 이력 행은
   데모 시드(`000021`)가 넣은 것이다.

즉 알림 규칙을 만들고 Slack webhook 을 등록해도 알림은 오지 않는다. 설정이 저장되므로
화면상으로는 동작하는 것처럼 보인다 — 이 항목의 위험은 거기에 있다. 3.5 B 로 되돌렸고,
기능목록 F7 도 "구현" 에서 "부분 구현" 으로 내렸다.

**교훈**: "타입이 있다" 를 "동작한다" 로 읽지 않는다. 다음 회차부터 이런 판정은
**호출부를 grep 해서 프로덕션 참조가 있는지 확인한 뒤**에만 해소로 옮긴다.

## 새로 드러난 코드 불일치

문서 작업 중 발견했으나 문서로는 고칠 수 없는 항목이다.

1. **`CompatibilityHandler.RegisterAdminRoutes` 가 등록되지 않았다.** 프런트는 이미
   `POST`·`PUT`·`DELETE /api/v1/admin/compatibility/matrices` 를 호출하므로,
   `/admin/stack-versions` 화면의 버튼 3개가 404 로 끝난다. 호환성 매트릭스를 늘리는
   유일한 경로가 마이그레이션 시드다.
2. **shadcn/ui 는 도입된 적이 없다.** 문서 6종이 사용법·초기화 명령까지 안내하고 있었으나
   `@radix-ui/*` 도 `shadcn` CLI 도 `package.json` 에 들어온 적이 없다. `components/ui/*` 는
   처음부터 손수 구현이었고 2026-08-11 개편에서 내부만 MUI 로 바뀌었다. 문서 쪽은 이번에
   고쳤고, 코드 쪽에 할 일은 없다.
3. **`golden_path_templates.created_by` 는 존재하지 않는다.** 테이블을 만드는 것은
   `000006` 이고 거기에 없다. `000008` 의 `CREATE TABLE IF NOT EXISTS` 에는 있지만 그때는
   테이블이 이미 있어 실행되지 않는다. 죽은 정의라 지우거나, 실제로 필요하면 `ALTER` 로
   추가해야 한다.
4. **`web/.env.example` 의 `VITE_OIDC_CLIENT_ID` 가 `nullus-web`** 이다. 실재하는 나머지는
   전부 `nullus-app` 이다 — `scripts/setup-keycloak.sh`(로컬 realm), `cd.yml` 기본값,
   `deploy/csp/zadara/values-zadara.yaml`. `.env.example` 을 그대로 복사해 로컬 OIDC 를
   켜면 realm 의 client 와 어긋나 **모든 API 가 401** 이 된다. 한 줄 수정이지만 코드라
   이번 회차에서 손대지 않고, OIDC 가이드에 경고를 달아 두었다.

## 검증 결과

- 엔드포인트 수와 경로는 각 핸들러의 `Register*Routes` 와 `cmd/api/main.go` 의 그룹 배선을
  기계적으로 결합해 산출했다. `RegisterAdminRoutes` 처럼 **정의됐지만 호출되지 않는** 것은
  제외했다(그래서 116개이지 119개가 아니다).
- 테이블·컬럼 수는 `db/migrations/*.up.sql` 을 순서대로 적용해 재구성했다.
  `CREATE TABLE IF NOT EXISTS` 가 이미 있는 테이블을 덮지 않도록 처리한 결과가 위 2번 발견이다.
- 시드 건수는 `INSERT`/`DELETE` 를 상쇄해 셌다 — 템플릿 9, 매트릭스 8, 파이프라인 템플릿 4.
