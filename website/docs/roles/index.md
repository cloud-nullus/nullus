# 역할별 사용법

Nullus 는 역할이 셋입니다. **누가 무엇을 하는 도구인지**가 역할마다 꽤 다르므로,
자기 역할 문서부터 보시면 빠릅니다.

<div class="nullus-cards" markdown>

[**Admin**<span>조직·사용자·클러스터를 세우고, 백업과 알림 채널을 관리한다. 메뉴 19개 전부가 보인다.</span>](admin.md)

[**DevOps**<span>스택을 설치하고 파이프라인을 만든다. 메뉴 11개가 보인다.</span>](devops.md)

[**Developer**<span>자기 앱을 배포하고 결과를 본다. 메뉴 4개가 보인다.</span>](developer.md)

</div>

[^1]: 사이드바에서는 가려지지만 라우트에 역할 제한이 없어 주소로는 열립니다. [권한 표](../reference/rbac.md#사이드바와-라우트가-어긋나는-곳) 참고.
[^2]: `/cicd/create` 는 라우트가 세 역할 모두 허용합니다. 다만 developer 의 사이드바에는 CI/CD 템플릿·골든패스가 없어서, 생성 버튼은 CI/CD 목록에서 들어갑니다.

## 역할은 어디서 정해지나

Keycloak 이 발급한 토큰의 역할을 프런트엔드가 읽어 저장합니다
(`web/src/stores/auth-store.ts` 의 `extractRoleFromOidc`). 즉 **역할은 Nullus 안에서
바꾸는 값이 아니라 IdP 에서 오는 값**입니다. 사용자에게 역할을 주는 화면은
[사용자 관리](../features/admin/users.md)입니다.
