# 사용자 관리

<span class="route">/admin/users</span>
<span class="role role-admin">admin</span>

조직 구성원을 추가하고 역할을 주는 화면입니다. 탭이 둘입니다.

## Users 탭

- 이름·이메일 검색, 역할 탭 필터
- 행마다 **역할 선택 상자** — 고르면 바로 저장됩니다
- **Deactivate** 버튼 (확인 창)
- **Edit** 창 — 이름·이메일·역할

### 사용자 추가 (Invite User)

이름 + 이메일 + 역할을 넣습니다. 이메일을 세 자 넘게 치고 `@` 가 들어가면 300ms
뒤 기존 사용자를 찾아보고, 있으면 이름을 자동으로 채웁니다.

!!! warning "메일은 가지 않습니다"
    이름이 "Invite" 지만 실제 동작은 이렇습니다.

    - 그 이메일의 사용자가 이미 있으면 → 조직 구성원으로 추가
    - 없으면 → 사용자 행을 **비활성(`is_active = false`)** 으로 만들고 구성원으로 추가

    **메일 발송도, 자격증명 생성도, 초대 토큰도 없습니다.** 새로 만든 사용자는
    비활성이라 로그인할 수 없습니다.

### Generate Invite Link

역할과 유효기간(1·3·7·30일, 기본 7일)을 고르면 링크를 클립보드에 복사합니다.

!!! danger "초대 링크 기능은 동작하지 않습니다"
    서버의 초대 엔드포인트 세 개가 **빈 응답을 돌려주는 자리막음**입니다
    (`{"items":[]}`, 빈 토큰, 204). 목록은 화면 안의 가짜 데이터를 보여 주고,
    생성이 실패하면 `inv-<타임스탬프>` 같은 **가짜 주소를 만들어 복사합니다.**

    게다가 `/invite/:token` 라우트가 앱에 없어서, 진짜 링크가 있어도 404 입니다.
    초대 수락 엔드포인트도 없습니다.

    지금 쓸 수 있는 길은 **기존 사용자를 이메일로 찾아 구성원으로 추가**하는
    것뿐입니다.

## Role Permissions 탭

!!! danger "이 탭은 아무 효력이 없습니다"
    권한 목록이 화면에 고정값으로 박혀 있고, View/Edit 칩을 눌러 **Save Changes**
    를 누르면 **브라우저 localStorage** 에 저장됩니다. 서버로 가지 않고, 실제
    권한을 바꾸지도 않습니다.

    실제 권한은 [권한 표](../../reference/rbac.md)에 적힌 대로 코드에 박혀
    있습니다.

## 호출하는 API

| 동작 | 엔드포인트 | 비고 |
|------|-----------|------|
| 이메일로 찾기 | `GET /api/v1/admin/users/search?email=` | 오류가 나도 `{found:false}` 를 돌려줍니다 |
| 구성원 목록 | `GET /api/v1/admin/organizations/{orgId}/members` | |
| 구성원 추가 | `POST …/members` | 감사 로그 남김 |
| 수정 | `PATCH …/members/{memberId}` | 한 항목 이상 필요. **감사 로그 없음** |
| 비활성화 | `POST …/members/{memberId}/deactivate` | `is_active=false` 만. **세션·토큰은 끊지 않습니다.** 감사 로그 없음 |
| 삭제 | `DELETE …/members/{memberId}` | 사용자 행을 **실제로 지웁니다** |

!!! warning "비활성화는 지금 접속 중인 사람을 끊지 않습니다"
    이미 발급된 토큰은 그대로 유효합니다. 즉시 차단이 필요하면 IdP(Keycloak)
    쪽에서 세션을 끊어야 합니다.

## 비밀번호 로그인에 대해

!!! danger "ID/PW 로그인은 어떤 계정으로도 성공할 수 없습니다"
    사용자 비밀번호 해시를 저장하는 자리와 해시를 만드는 함수는 있지만,
    **제품 코드 어디에서도 그 값을 쓰지 않습니다.** 시드도, 구성원 추가도
    해시를 넣지 않습니다.

    따라서 비상용 비밀번호 로그인은 운영자가 데이터베이스에 bcrypt 해시를 직접
    넣어 주지 않으면 쓸 수 없습니다. 정상 경로는 Keycloak OIDC 입니다.
